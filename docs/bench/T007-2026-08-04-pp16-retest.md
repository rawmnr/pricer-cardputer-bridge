## Objective

Retest a deterministic 208 x 112 all-black PP16 image sequence with the emitter placed closer to the ESL, then correct a source-level PP16 ordering defect found by comparison with the cited PrecIR transmitter.

## Input sequence

The host generated and transmitted these finalized PP16 frames:

1. PP16 wake frame, 100 repeats, 1,000 us inter-repeat gap; repeated four times (400 wake frames total).
2. Image-parameter frame for 208 x 112.
3. Compressed all-black image-data frame.
4. Refresh frame.

The installed application accepted every request on `COM3`. The host transport reported `wake x400 + black page params/data/refresh accepted on COM3`.

## Observed result

- The ESL did not visibly update after the closer-emitter retest.
- The installed application was still the pre-fix firmware; the candidate binary was built but not installed during this run.
- Windows exposed the Cardputer bridge as `COM3` throughout the accepted sequence.
- No optical receiver response, waveform capture, carrier measurement, or ESL acknowledgement was available.

## Source correction

Commit `d845951` changes both host and firmware PP16 encoders to emit each byte low nibble first, then high nibble. This matches the inspected PrecIR transmitter implementation. Golden host and firmware unit expectations were updated, and the protocol documentation now records the ordering. The correction remains physically unvalidated until this candidate application is installed through M5Launcher and the sequence is repeated.

## Conclusion

The closer-emitter test with the pre-fix installed firmware did not update the ESL. The source now follows the low-nibble-first order used by the inspected PrecIR transmitter, but no compatibility claim is made until the candidate binary is installed and the physical test is repeated.
