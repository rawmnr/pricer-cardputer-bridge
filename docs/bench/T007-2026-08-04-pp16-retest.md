## Objective

Retest a deterministic 208 x 112 all-black PP16 image sequence with the emitter placed closer to the ESL, then correct a source-level PP16 ordering defect found by comparison with the cited PrecIR transmitter.

## Input sequence

The host generated and transmitted these finalized PP16 frames:

1. PP16 wake frame, 100 repeats, 1,000 us inter-repeat gap; repeated four times (400 wake frames total).
2. Image-parameter frame for 208 x 112.
3. Compressed all-black image-data frame.
4. Refresh frame.

- The host transport accepted every request on `COM3` in both the pre-fix and corrected-frame runs.

## Observed result

- The ESL did not visibly update after either closer-emitter retest.
- After the candidate was copied to the SD card and launched, the application still reported firmware `0.1.0`; the version string was unchanged, so candidate installation cannot be distinguished from the prior application by `HELLO` alone.
- The corrected-frame run used MCU commands `0x05` (parameters), `0x20` (data), and `0x01` (refresh); the earlier generated frames had an erroneous extra `0x34` before those commands.
- Windows exposed the Cardputer bridge as `COM3` throughout the accepted sequences.
- No optical receiver response, waveform capture, carrier measurement, or ESL acknowledgement was available.

## Source correction

Commit `144796b` changes both host and firmware PP16 encoders to emit each byte low nibble first, then high nibble. This matches the inspected PrecIR transmitter implementation. Golden host and firmware unit expectations were updated, and the protocol documentation now records the ordering.

## Artifacts and evidence limits

- Candidate application binary: `firmware/.pio/build/m5stack-cardputer-adv/firmware.bin`
- Raw frame artifacts: temporary files under `%TEMP%` at test time; not retained in the repository
- Host result: accepted bridge responses for all frame requests in both runs.
- Physical result: no visible ESL update; this does not distinguish firmware installation state, frame layout, timing, carrier, optical alignment, or target identification.

## Conclusion

Neither the pre-fix nor corrected-command run produced a visible ESL update. The source now follows the low-nibble-first order used by the inspected PrecIR transmitter, but the firmware build identity is not exposed separately from version `0.1.0`, and no physical compatibility claim can be made without waveform and receiver evidence.
